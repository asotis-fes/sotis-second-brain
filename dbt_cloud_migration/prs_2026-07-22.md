### 2. fes-airflow #2306 — COPY GRANTS on create_tables/sql
- **URL**: https://github.com/fanatics-gaming/fes-airflow/pull/2306
- **Branch**: `fix/create-tables-copy-grants` (fresh off `main`)
- **Diff**: 83 files, 95 CREATE OR REPLACE statements modified (175 insertions, 95 deletions)
- **What it does**: adds `COPY GRANTS` to CREATE OR REPLACE statements for `TABLE` and `EXTERNAL TABLE` — prevents nightly rebuilds from wiping direct grants
- **Covers**:
  - Regular tables — `COPY GRANTS` placed between name and `(`/`AS`
  - External tables — `COPY GRANTS` placed as last clause before `;`, after `FILE_FORMAT`
- **Does NOT cover** (KEY GAP):
  - **17 ICEBERG TABLE files** — Snowflake's `CREATE OR REPLACE ICEBERG TABLE` with AWS Glue external catalog does **not accept COPY GRANTS**. Verified against docs.snowflake.com. Full list in the PR body.
  - No VIEW / DYNAMIC TABLE files exist in `create_tables/sql/`
- **Iceberg-gap consequence**: Every time an ingest DAG rebuilds an iceberg table (e.g. Ecomm's daily rebuild of `COMMERCE.SOURCE.SES_CLICKS_ICEBERG`), all direct grants get wiped. Reads keep working IF the reader's role holds a db-role whose SELECT is reapplied by schema-level future grants. If a role needs direct SELECT (not via db-role), that access breaks each rebuild. This is Rohan's original class of failure.
- **Suggested iceberg follow-up**: verify `FUTURE GRANTS` on `COMMERCE.SOURCE` (and equivalent schemas) fire on `CREATE OR REPLACE` and cover iceberg tables specifically. If yes, one-shot fix via TF. If no, per-DAG explicit `GRANT SELECT ON ICEBERG TABLE ...` after each CREATE OR REPLACE.
