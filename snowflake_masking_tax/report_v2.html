Snowflake Masking Tax — Experiment Matrix

Run ID 20260610a · alex.sotis@betfanatics.com · 2026-06-10 · V2: quadrant layout

What this experiment measures

Quantify the wall-clock and credit cost of adopting Snowflake column masking policies on FES Data workloads. Four phases, increasing realism: a smoke test, a per-row-cost microbenchmark, a production-realistic dbt model rebuild, and a real consumer query pattern (Growthloop).

Each phase tests a defined matrix of policy variants (no masking, SHA2 hash, constant-return, role-conditional) and role contexts (user has PII access vs. doesn't). The view-based PII handling alternative is out of scope.

Findings

  • Production scenario (pipeline allowlisted, plaintext branch): essentially zero tax. HASH/plaintext came in at 282.2 s vs 287.7 s baseline (−1.9%, within noise); CONST/plaintext at 275.6 s (−4.2%, also noise). With Airflow's service role in the policy allow-list, the masking adds no measurable cost to the daily fangraph rebuild on the prod 3XL warehouse.
  • Pessimistic scenario (pipeline NOT allowlisted, masked branch): hash masking essentially free (−0.2%, within noise); constant masking actually 14.5% faster than baseline — the optimizer elides the column scan for constant projections.
  • HASH/plaintext ≈ CONST/plaintext (282.2 s ≈ 275.6 s) — confirms both hit the THEN val branch; the unused ELSE doesn't matter.
  • Correctness caveat: if masked sources feed the column_intersection_row_hash macro, deterministic masking (SHA2 or const) means upstream PII changes won't trigger row-hash mismatches — fangraph_last_updated_timestamp won't bump. Argues against masking source tables for change-detection-dependent models.
  • Two-day caveat: baselines were 291.1 s (3-rep median, 2026-06-10) vs 287.7 s (single rep, 2026-06-11) — within 1.2% of each other. Plaintext-branch deltas are computed against same-day baseline (287.7); masked-branch deltas use the day-before baseline (291.1). Underlying clones are zero-copy of FANGRAPH.ADMIN.FANGRAPH_BASE/_SNAPSHOTS at their respective points in time.
  • Verified controls: zero warehouse contention; all runs on 3XL; result cache disabled; cold-start consistent.

Findings

Findings

  • Small warehouse DOES show measurable tax on the masked branch (+24%) — significantly less than Phase 2's microbenchmark predicted (+110–180%) but not zero like Phase 3 (3XL, ~0%) and Phase 4 (Large, +5%). Warehouse size matters; smaller warehouses have less parallelism to absorb per-row mask cost.
  • Plaintext branch is still essentially free (−4.5% to −5.2%, within noise) regardless of warehouse size. Users with PII access never see meaningful slowdown.
  • Const masking is >25% faster than baseline on the masked branch — optimizer elides constant projections even on Small. Same effect as Phase 3 (3XL) and Phase 4 (Large). The cost saving compounds at smaller warehouse sizes.
  • Const masking changed semantics: CONST/EXCLUDED produced 41.9M rows vs baseline's 41.1M because NULL fangraph_last_name becomes '***MASKED***', bypassing the IS NOT NULL WHERE filter. Worth flagging — semantic correctness, not just performance.
